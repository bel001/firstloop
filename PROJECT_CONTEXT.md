# FIRSTLOOP — Project Context

> **Ideas become projects. Projects become teams. Teams build the future.**

## 1. Project Overview

**FIRSTLOOP** is an AI-powered collaborative project creation and team formation platform.

It helps people transform ideas into structured projects, discover the right collaborators, join existing initiatives, and work together to turn ideas into real outcomes.

FIRSTLOOP addresses a common problem: people have ideas, skills, creativity, and motivation, but they often lack the connections, complementary expertise, or experience needed to make their ideas happen.

Instead of requiring users to already have a team, FIRSTLOOP helps them build one.

Instead of requiring users to have an idea, FIRSTLOOP allows them to discover projects where they can contribute, collaborate, and learn.

### Core Value Proposition

**Anyone can start building something meaningful, even without having all the skills or knowing the right people.**

FIRSTLOOP uses artificial intelligence to understand projects, identify missing capabilities, recommend complementary collaborators, and help teams organize their first steps.

Build a global platform where ideas and people can find each other, regardless of their academic background, professional experience, location, or discipline.

We envision a world where:

- People do not abandon ideas because they cannot find collaborators.
- Students can gain practical experience by participating in real projects.
- Developers can find designers, artists, writers, researchers, and other specialists.
- Creative people can turn concepts into collaborative projects.
- Beginners can contribute while learning.
- Interdisciplinary teams can form without depending exclusively on personal connections.

### Mission

Make collaboration more accessible by using AI to connect people with complementary skills and help them build things together.

## 3. The Problem

Many people want to create something but struggle with the process of finding and organizing the right collaborators.

The main problems are:

### 3.1 Ideas without teams

Someone may have an interesting idea but lack the technical, creative, or specialized skills required to develop it.

### 3.2 Skills without opportunities

People possess useful skills but do not know which projects need them or how to find suitable collaborators.

### 3.3 Lack of experience

Students and beginners often struggle to join meaningful projects because they have limited experience or portfolios.

### 3.4 Fragmented collaboration

People use multiple platforms to discover collaborators, communicate, organize tasks, and manage projects.

### 3.5 Difficulty structuring ideas

Many people know what they want to create but do not know how to define an MVP, identify required roles, select technologies, or organize the development process.

FIRSTLOOP aims to connect these disconnected stages in one coherent experience.

## 6. Core Product Experience

FIRSTLOOP has two primary entry points.

### Path A — I Have an Idea

A user wants to build something but does not have the complete team.

The user describes the idea using natural language.

FIRSTLOOP then:

1. Understands the idea.
2. Identifies the problem and intended outcome.
3. Structures the project.
4. Suggests a realistic MVP.
5. Identifies required skills and roles.
6. Determines which roles are essential and optional.
7. Searches for suitable collaborators.
8. Explains why each candidate matches.
9. Allows the project owner to invite or accept collaborators.
10. Creates an initial collaborative workspace.

The user remains in control of all project decisions.

### Path B — I Want to Participate

A user wants to contribute to an existing project.

FIRSTLOOP allows the user to:

1. Create a personal skills and interests profile.
2. Specify availability and collaboration preferences.
3. Discover relevant projects.
4. Receive personalized recommendations.
5. Understand the responsibilities of each available role.
6. Apply to participate.
7. Receive acceptance or rejection.
8. Join the project workspace.
9. Contribute to tasks and milestones.

Users should be able to participate as learners, collaborators, mentors, professionals, or potential co-founders.

## 7. Core Features

### 7.1 AI Project Architect

Transforms unstructured ideas into structured project blueprints.

The system should identify:

- Project title.
- Description.
- Problem being addressed.
- Intended users.
- Main objectives.
- Expected outcome.
- Proposed MVP.
- Suggested technologies.
- Required skills.
- Required roles.
- Optional roles.
- Initial milestones.
- Potential challenges.

The generated blueprint must be editable and approved by the project owner before publication.

### 7.2 AI Team Architect

Analyzes the project blueprint and determines what kind of team is required.

It should:

- Identify missing capabilities.
- Define role responsibilities.
- Distinguish essential and optional positions.
- Identify dependencies between roles.
- Recommend a minimum viable team.
- Avoid recommending unnecessarily large teams.

### 7.3 AI Talent Matcher

Finds collaborators whose skills, interests, availability, and expectations align with project requirements.

The matching process must consider:

- Required skills.
- Complementary capabilities.
- Experience and learning potential.
- Availability.
- Interests.
- Collaboration preferences.
- Language compatibility.
- Compensation and participation conditions.

Every recommendation should include an understandable explanation.

A compatibility score must represent an estimated fit, not a guarantee of successful collaboration.

### 7.4 Project Explorer

Allows users to discover projects created by other people.

It should support:

- Search.
- Categories.
- Skill filters.
- Availability filters.
- Experience levels.
- Remote and location-based preferences.
- Recommended projects.
- Open roles.
- Project details.

### 7.5 Applications and Invitations

Allows users to request participation and project owners to manage applications.

Each application should include:

- User profile.
- Selected role.
- Motivation.
- Relevant skills.
- Availability.
- Optional portfolio or evidence.

Project owners must approve applications explicitly.

### 7.6 Collaborative Project Workspace

Once a team is formed, FIRSTLOOP creates a shared environment.

The workspace should support:

- Project overview.
- Team members.
- Roles and responsibilities.
- Task management.
- Milestones.
- Progress tracking.
- Comments.
- Contribution records.
- Basic notifications.

### 7.7 AI Project Coach

Helps teams organize their work.

It should:

- Generate initial tasks.
- Suggest task assignments.
- Identify dependencies.
- Recommend milestones.
- Explain technical or organizational concepts.
- Identify potential blockers.
- Suggest ways to improve project execution.

The AI should assist the team rather than make decisions on behalf of its members.

### 7.8 Contribution Tracking

Records contributions and project progress.

The platform must distinguish between:

- Declared contribution.
- Work in progress.
- Submitted work.
- Accepted work.
- Independently verified contribution.

The system must never claim that an unverified contribution has been completed or approved.

## 8. Main Innovation: AI Project-to-Team Engine

The central innovation of FIRSTLOOP is the integration of project understanding, team architecture, intelligent matching, and team composition.

The objective is not simply to recommend individuals.

The objective is to identify a combination of people that collectively covers a project's needs.

### Processing Pipeline

**Input: Project Idea + User Profile**

↓

**1. Project Understanding**

Extracts the project's objectives, requirements, constraints, and expected outcomes.

↓

**2. Team Architecture**

Creates a structured representation of the skills, roles, and responsibilities required.

↓

**3. Candidate Retrieval**

Finds relevant people using profile information, structured filters, and semantic search.

↓

**4. Intelligent Matching**

Evaluates individual compatibility and team-level skill coverage.

↓

**5. Team Composition**

Recommends a balanced combination of collaborators.

↓

**6. Human Approval**

The project owner reviews candidates and decides whom to invite.

↓

**7. Project Launch**

Creates the initial workspace, tasks, and milestones.

### Team Balance Optimization

FIRSTLOOP should explore team-level optimization rather than relying exclusively on individual recommendation scores.

For example, if a project needs:

- One backend developer.
- One frontend developer.
- One visual designer.
- One domain specialist.

The system should prioritize combinations that cover these needs while respecting availability, preferences, and collaboration constraints.

The objective is to maximize useful skill coverage and compatibility, not simply select the four highest-scoring profiles.

This capability is a key technical differentiation hypothesis and should be validated through real user testing.

## 9. AI System Design

The application should use specialized AI components with clearly defined responsibilities.

### Project Architect

Understands ideas and generates structured project blueprints.

### Team Architect

Analyzes project requirements and defines the ideal team structure.

### Talent Matcher

Retrieves and evaluates suitable collaborators.

### Project Coach

Supports project planning, task creation, and execution.

### Contribution Auditor

Organizes contribution evidence and verifies supported completion states.

These components may be implemented as separate services or specialized workflows.

The initial MVP should prioritize reliability and simplicity over unnecessary agent complexity.

### AI Principles

- Use structured outputs for project and role generation.
- Validate model-generated data before storing it.
- Keep matching calculations explainable.
- Never invent user qualifications or project evidence.
- Allow users to correct AI-generated information.
- Require human approval for invitations and important actions.
- Respect user privacy and permissions.
- Avoid making judgments based on protected or sensitive personal attributes.

## 10. Matching Algorithm

The matching engine should combine deterministic rules, structured skill information, and semantic similarity.

An initial matching model may consider:

| Factor | Initial Weight |
|---|---:|
| Required skills | 30% |
| Complementary capabilities | 20% |
| Availability | 15% |
| Shared interests | 15% |
| Experience and learning potential | 10% |
| Collaboration preferences | 10% |

These weights are initial hypotheses, not final validated parameters.

The system should also apply hard constraints when necessary, including:

- Required availability.
- Language requirements.
- Compensation preferences.
- Collaboration modality.
- Role-specific mandatory skills.

The algorithm should provide an explanation of the recommendation.

### Learning-Oriented Matching

FIRSTLOOP should recognize that not every contributor needs to be an expert.

The platform should distinguish:

- Skill Match: the person already has the required capabilities.
- Growth Match: the person can contribute to an accessible part of the project while developing relevant skills.

Learning-oriented participation must be transparent and should never be used to justify assigning people responsibilities they are not prepared to handle.

## 15. Security, Privacy, and Collaboration Rules

FIRSTLOOP connects people who may not know each other.

The platform must therefore prioritize trust and safety.

Required principles:

- Secure authentication.
- Role-based authorization.
- Private user information by default.
- Consent before sharing personal information.
- Reporting and blocking functionality.
- Protection against unauthorized access.
- Validation of external links.
- Clear project ownership.
- Transparent collaboration conditions.
- Explicit agreements concerning intellectual property.

Every project should declare whether participation is:

- Voluntary.
- Paid.
- Equity-based.
- Open-source.
- Educational.
- Another explicitly defined arrangement.

Users should understand responsibilities and ownership expectations before joining.

## 16. Product Differentiation

Existing platforms already provide project listings, collaborator discovery, co-founder matching, and AI-assisted recommendations.

FIRSTLOOP should not claim that these individual capabilities are entirely new.

Its differentiation hypothesis is the integrated experience:

1. Understand an unstructured idea.
2. Convert it into an actionable project.
3. Design the team required to build it.
4. Find complementary collaborators.
5. Optimize the composition of the team.
6. Help members start working together.
7. Track actual progress and contributions.

The central product focus is the transition from idea to team to execution.

## 17. Success Metrics

The primary metric should be:

**Successfully Launched Teams**

A launched team is a project where:

- The owner has approved the team.
- The required collaborators have accepted their roles.
- The project workspace has been created.
- At least one initial task has been assigned.

Additional metrics:

- Project creation completion rate.
- Percentage of projects with suitable candidates.
- Match acceptance rate.
- Time from publication to first accepted collaborator.
- Team formation rate.
- Percentage of teams completing their first milestone.
- User retention.
- User satisfaction with matching recommendations.

The number of registrations alone should not define product success.
